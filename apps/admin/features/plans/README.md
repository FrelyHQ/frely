# Plans feature

The route owns authentication, authorization, the initial repository read, DTO allowlisting, and the authoritative Plan Template / Plan / Budget Policy lists. This feature owns only draft, selection, dialog and notice state, typed Admin API calls, TanStack Form lifecycle, TanStack Query mutations, and TanStack Table presentation. Mutation responses are not merged into persistent client list copies; each successful operation performs one RSC refresh. Policies created while creating a template remain local to that transaction until refresh.

Plan commercial terms are server-authoritative. Mutations are never retried or applied optimistically. Existing subscription terms, access entitlements, budget bindings, duration, billing mode, and price overrides remain subject to the Plan-version rules in `docs/baseline/billing-plan-and-usage-limits.md`; the browser only performs immediate input checks. Ledger, billing, and audit facts remain append-only and are not editable here. No credential, authorization value, or payment secret enters a query key or cache.

Subscription overview/detail, creation, and cancellation live under `features/plans/subscriptions`; `PlanManagement` contains only Plan-template state and mutations. Subscription cancellation uses the dedicated Admin cancel action, asks for explicit confirmation, and refreshes the RSC view after success. It stops access by setting the lifecycle to `canceled` and truncating `effective_end`; it never deletes the Subscription or optimistically changes Plan, ledger, billing, settlement, or audit data.
